# Contributing to Problem Intelligence OS (PIOS)

Thank you for contributing to PIOS! Please follow these architectural principles and workflows.

---

## Architectural Rules

1. **5-Layer Separation**:
   - `Router -> Service -> Repository -> SQLAlchemy -> PostgreSQL`
   - Do NOT write raw SQL or database queries in Router endpoints.
2. **Pydantic Contracts**: Use Pydantic schemas for API inputs and outputs.
3. **Database Migrations**: Always use Alembic for schema evolution. Inspect autogenerated migration scripts before applying them.
4. **Test Isolation**: Never run tests against the development database (`problem_intelligence`). Use the test suite setup which isolates tests to `problem_intelligence_test`.
5. **Engineering Log**: Keep `Engineering_Log.md` updated with every sprint change, rationale, problem, solution, and test result.
